# Closely AI - Metrics Dictionary

This document defines the metrics and Key Performance Indicators (KPIs) used to measure system availability, recommendation quality, and business performance across all tenant organizations.

---

## 1. AI Containment

* **Name**: AI Containment
* **Purpose**: Measures the efficiency of the AI sales employee in handling customer interactions completely without requiring human agent takeover.
* **Formula**:
  $$\text{Containment Rate} = \frac{\text{Conversations Completed without Human Takeover}}{\text{Total Conversations}}$$
* **Data Source**: `conversations` database table (filter by `status != 'human_takeover'`).
* **Update Frequency**: Hourly
* **Owner**: Analytics Lead
* **Dashboard Location**: Merchant Dashboard Console (Main page summary card)
* **Alert Threshold**: $< 60\%$ (Triggers an operational alert for manual review of intent logs)

---

## 2. Average Latency (AI Generation)

* **Name**: Average Latency
* **Purpose**: Monitors the responsiveness of the AI orchestrator pipeline to ensure conversational fluidness.
* **Formula**:
  $$\text{Average Latency} = \frac{\sum \text{Message Generation Time (ms)}}{\text{Total Messages Automated}}$$
* **Data Source**: API execution metrics / structured logs (`generate_reply` execution duration).
* **Update Frequency**: Real-time / Hourly
* **Owner**: AI Pipeline Engineer
* **Dashboard Location**: Prometheus / Grafana Developer Dashboard
* **Alert Threshold**: Average $> 2.0\text{ s}$ over a 5-minute rolling window.

---

## 3. Webhook Acknowledgment Rate

* **Name**: Webhook Acknowledgment Rate
* **Purpose**: Verifies that the Meta Cloud API webhook endpoint acknowledges payloads fast enough to avoid Meta retries or endpoint blocking.
* **Formula**:
  $$\text{Ack Rate} = \frac{\text{Webhooks responded to with } 200 \text{ OK in } \le 500\text{ms}}{\text{Total Webhooks Received}}$$
* **Data Source**: Webhook controller logs (ingress times).
* **Update Frequency**: Real-time
* **Owner**: Integrations Lead
* **Dashboard Location**: Prometheus / Grafana Developer Dashboard
* **Alert Threshold**: $< 99.0\%$ over a rolling 24-hour window.

---

## 4. Estimated Synthetic Revenue

* **Name**: Estimated Synthetic Revenue
* **Purpose**: Records simulated sales conversions generated by the automated checkout system during testing/simulation phases.
* **Formula**:
  $$\text{Estimated Revenue} = \sum \text{Total Amount of Orders in 'completed' status} \quad (\text{Simulated})$$
* **Data Source**: `orders` database table (filtered by tenant organization ID).
* **Update Frequency**: Hourly
* **Owner**: Product Owner
* **Dashboard Location**: Merchant Dashboard Console (Sales & Invoices tab)
* **Alert Threshold**: N/A (Diagnostic metric only)

---

## 5. Simulated Evaluation Score

* **Name**: Simulated Evaluation Score
* **Purpose**: Aggregates qualitative pilot merchant feedback score to measure product satisfaction prior to paying contract conversion.
* **Formula**:
  $$\text{Evaluation Score} = \text{Average score rated by the merchant } (0-10)$$
* **Data Source**: Merchant post-pilot interview scorecard (`evaluation.md`).
* **Update Frequency**: Per pilot execution
* **Owner**: Support Lead
* **Dashboard Location**: Pilot Scorecard documentation
* **Alert Threshold**: $< 8/10$

---

## 6. Human Takeover Rate

* **Name**: Human Takeover Rate
* **Purpose**: Tracks how frequently conversations transition from AI control to manual human intervention.
* **Formula**:
  $$\text{Takeover Rate} = \frac{\text{Conversations with status 'human_takeover'}}{\text{Total Conversations}}$$
* **Data Source**: `conversations` database table.
* **Update Frequency**: Hourly
* **Owner**: Operations Lead
* **Dashboard Location**: Merchant Dashboard Console (takeover rate trend chart)
* **Alert Threshold**: $> 35\%$ (Indicates catalog mismatch, policy confusion, or high volume of custom sizing requests)

---

## 7. Catalog Ingestion Success Rate

* **Name**: Catalog Ingestion Success Rate
* **Purpose**: Verifies the stability of the uploader and the compliance of merchant catalogs with database standards.
* **Formula**:
  $$\text{Ingestion Success Rate} = \frac{\text{Completed imports without validation error}}{\text{Total catalog CSV uploads initiated}}$$
* **Data Source**: Catalog upload endpoint logs.
* **Update Frequency**: Weekly
* **Owner**: Backend Engineering Role
* **Dashboard Location**: Admin Console / Logs
* **Alert Threshold**: $< 95\%$

---

## 8. Recommendation Quality KPIs

To trace recommendation quality and optimize ranking engines using real-world interactions rather than intuition:

### A. Recommendation Click-Through Rate (CTR)
* **Purpose**: Measures customer interest in AI recommended product SKUs.
* **Statistical Validity**: Requires a minimum sample size of **$N \ge 100$ recommendations shown** in the measurement window to prevent ratio distortion from sparse data.
* **Formula**:
  $$\text{CTR} = \frac{\text{Recommendations Clicked}}{\text{Total Recommendations Shown}}$$
* **Data Source**: Telemetry event logs (`recommendation_feedback` telemetry dataset).
* **Update Frequency**: Weekly
* **Owner**: AI Engineering Role
* **Alert Threshold**: $< 10\%$

### B. Recommendation Acceptance Rate
* **Purpose**: Monitors how often AI recommendations are dispatched without merchant takeovers or overrides.
* **Formula**:
  $$\text{Acceptance Rate} = \frac{\text{Recommendations Sent on Autopilot} + \text{Approved by Merchant}}{\text{Total Recommendations Generated}}$$
* **Data Source**: Telemetry event logs.
* **Update Frequency**: Weekly
* **Owner**: Product Role
* **Alert Threshold**: $< 70\%$

### C. Merchant Override Rate
* **Purpose**: Tracks how frequently manual agents reject or edit AI-suggested product recommendation cards.
* **Formula**:
  $$\text{Override Rate} = \frac{\text{Recommendations Rejected / Edited}}{\text{Total Recommendations Generated}}$$
* **Data Source**: Telemetry event logs.
* **Update Frequency**: Weekly
* **Owner**: Product Role
* **Alert Threshold**: $> 25\%$ (indicates need for prompt or catalog tuning)

### D. Recommendation-to-Purchase Conversion
* **Purpose**: Tracks actual transaction conversions influenced by recommended items.
* **Statistical Validity**: Requires a minimum sample size of **$N \ge 100$ recommendations shown** in the measurement window.
* **Formula**:
  $$\text{Conversion Rate} = \frac{\text{Recommendations resulting in Completed Checkout Payments}}{\text{Total Recommendations Shown}}$$
* **Data Source**: Combined `orders` and telemetry event logs.
* **Update Frequency**: Weekly
* **Owner**: Product Role
* **Alert Threshold**: $< 3\%$

### E. Precision@K
* **Purpose**: Evaluates candidate retrieval accuracy against goldens and historical search sessions.
* **Tracking Rules**: To prevent historical drift interpretation errors, every logged Precision@K score must explicitly record:
  1. *Evaluation Dataset Version* (e.g. `v1.2- Bangalore-boutique-catalog`)
  2. *Golden Dataset Version* (e.g. `v2.4-intent-goldens`)
  3. *Active LLM Model Version* (e.g. `gemini-2.5-flash`)
* **Formula**:
  $$\text{Precision@K} = \frac{\text{Relevant items retrieved in top K positions}}{K}$$
* **Data Source**: Offline AI Evaluation suite.
* **Update Frequency**: Continuous integration / deploy validation
* **Owner**: AI Engineering Role
* **Alert Threshold**: $< 80\%$ on release-blocking evaluation sets.

## 9. Metric Governance & Small-Team Role Mappings

> [!NOTE]
> **Role-Based Governance**: The owners defined in this metrics dictionary represent functional **roles** rather than dedicated individuals. In early-stage development (such as MVP staging and boutique pilots), these roles collapse onto the active developers and founders. As the organization grows, these role responsibilities will map onto specialized hires (Data Science, DevOps, QA, Support Operations).
